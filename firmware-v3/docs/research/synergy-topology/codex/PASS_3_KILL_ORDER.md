# PASS 3 - KILL ORDER

## Metric Definition

Unlock surface is expressed as:

`(modes-renderable) x (layer-stack depth supported) x (independent parameter axes per mode) x (composition primitives in the LayerStack alphabet)`

The headline integer is the product. This is a comparative planning metric, not a claim that every combination is launch-quality. I use 106 as the current mode/programme baseline because the ProductStrategy SSA references 106 ambient programmes, while the codebase map confirms the firmware has a much larger 350+ effect implementation surface. If Captain chooses a different production-visible mode count, every product below scales linearly. Evidence: ProductStrategy lines 43-54; codebase-map effect-system note.

Current K1 baseline:
  Step 0 tuple: (106 modes) x (1 depth) x (8 global axes) x (1 no-overlap primitive) = 848
  Axes counted: brightness, speed, palette, hue, intensity, saturation, complexity, variation from REST/WS parameter contracts.
  Caveat: current per-effect parameter counts vary; the metric uses the common control surface only.

## GREEDY vs STRATEGIC COMPARISON

Greedy order:
  1. D04 LayerStack
  2. D05 ControlBus render reuse
  3. D03 Global LPF
  4. D09 Cross-strip interference
  5. D06 Tempo phase
  6. D10 Frame ring
  7. D14 Long-context state
  8. D11 Physics fields

Strategic order:
  1. D15 Product filter and D01 centre-origin audit
  2. D08 PersistenceHelpers
  3. D03 Global LPF
  4. D04 LayerStack
  5. D05 ControlBus render reuse
  6. D07 dot cache
  7. D06 single tempo phase
  8. D12 pitch geometry
  9. D09 dual-strip moat
  10. D14/D16/D13 ambient and ritual
  11. D10 frame ring
  12. D11 physics

Divergence points:
  Greedy would implement LayerStack first because it creates the largest immediate tuple gain. Strategic puts PersistenceHelpers and LPF first so LayerStack does not produce hard, visually muddy stacks.
  Greedy would jump to cross-strip interference early because it is demo-shocking. Strategic waits until phase and composition primitives exist so it can be a product-quality pillar, not a one-off.
  Greedy would push frame history before ambient state because it expands the alphabet. Strategic ships Liquid Stillness and First-Light earlier because they satisfy the premium product promise.

Recommendation:
  Follow the strategic order. The greedy order maximises the arithmetic surface earlier, but it risks building a large uncurated possibility space before the primitives that make it liquid, centre-origin and product-correct. The hidden hub not captured by raw surface is D15; it prevents wasted implementation of high-surface but brand-wrong effects.

## LEFT ON THE TABLE

[D17] External Control / Tab5 Turbulence - reason excluded from core order: singleton and protocol-dependent. Conditions under which it becomes critical: Captain wants a playable live-demo surface or Tab5 is bundled as a primary launch controller.

[D18] Perceptual Hardware Calibration - reason excluded from core order: corpus lacks enough direct calibration evidence. Conditions under which it becomes critical: camera capture, production diffuser variance or brightness complaints become launch blockers.

[Full ES Tempo Bank] - reason excluded: ProductStrategy rejects literal N-pendulum rendering and recommends single-tempo first. Conditions under which it becomes critical: future effect families need polytempo or per-chroma phase rather than one dominant phase.

[D11 advanced Kuramoto/Boids/pendulum chain] - reason excluded: visually unproven and hardware A/B required. Conditions under which it becomes critical: Liquid Bloom and Cross-Strip Interference are not visually distinctive enough in hardware capture.

[D13 ambitious DSP: formants, modulation spectrum] - reason excluded: higher validation cost and less immediate product value than render-side reuse. Conditions under which it becomes critical: K1 pivots toward vocal/music interpretation as a signature differentiator.

[Story-Arc Sequencer] - reason excluded: authoring-tooling heavy. Conditions under which it becomes critical: real user/music captures create repeatable scenes worth choreographing.

[History-buffer "scope" modes] - reason excluded: ProductStrategy kill-list rejects analyser/test-fixture aesthetics; only centre-origin radial onset history is exempt. Conditions under which it becomes critical: diagnostic or composer tooling, not launch effects.
